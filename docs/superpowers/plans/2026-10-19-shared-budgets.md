# Shared Budgets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let several users keep one budget together: a shared category tree with monthly amounts, each member mapping their own categories onto it, and a report of totals plus a per-member split that never reads members' books at view time.

**Architecture:** A third SQLite schema — one file per shared budget at `<data_dir>/shared/<id>.db` (shared categories, amounts, per-member tallies) — with a registry (budgets, members) in `server.db` and each member's mappings in their own books. A books-session `after_commit` hook recomputes the committing member's tally in every shared budget they belong to; startup, restores and joins rebuild it.

**Tech Stack:** FastAPI, SQLAlchemy 2 ORM, Alembic (multi-tree via `alembic.ini` sections), SQLite, pytest; React + TypeScript + Vite, Vitest + React Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-19-shared-budgets-design.md`

## Global Constraints

- Any SQLAlchemy model change ships with an Alembic migration in the matching tree, generated by autogenerate and read before committing (CLAUDE.md). Never edit a committed migration.
- Never touch `backend/budgeter.db`, `backend/server.db` or `backend/books/`; autogenerate against scratch paths only (commands in CLAUDE.md, and Task 1 for the new tree).
- Books tables never carry a user id. `member_tallies.user_id` lives in the shared file, not books.
- Bare `sqlite://` (tests) skips all migrations; shared files then use per-budget in-memory `StaticPool` engines with `create_all`, like books.
- Non-members get 404 (`NotFoundError`) on every shared-budget route — never 403.
- Services raise `app.errors` domain errors; routers don't build HTTPExceptions for them.
- Tally amounts are raw signed sums of `Split.amount` (spending negative). Only the report applies the sign convention: actual = −sum; for categories that are income (own or inherited `is_income`) actual = +sum.
- Run backend tests from `backend/` with `.venv/bin/pytest`; frontend tests from `frontend/` with `npm test -- --run`.

**Deviations from the spec found while planning** (books engines don't enable `PRAGMA foreign_keys`, so `ON DELETE CASCADE` on `shared_category_links.category_id` would never fire): the FK is still declared, but a link whose category no longer exists (only possible by undoing a category's creation — categories are otherwise only archived) is skipped by the recompute and pruned by the next `PUT …/links`, exactly like a stale shared-category link. Shared files *do* enforce foreign keys (Task 1), so their cascades are real.

## Review Focus

1. A member with a parent category linked to shared A and a child linked to shared B: the child's spending counts once, under B only (Task 4 test `test_most_specific_link_wins`).
2. Splits with `category_id = NULL` (transfers, uncategorised) and splits in unmapped categories never reach the tally (Task 4 `test_unmapped_and_uncategorised_splits_ignored`).
3. A member who has mapped nothing still appears in the report's per-member split with zeros (Task 5 `test_report_lists_every_member_even_without_links`).
4. A member who removes themselves immediately loses access (404) and their tally disappears from the report (Task 6 `test_leaving_removes_access_and_tally`).
5. Reparenting a shared category under its own descendant is rejected with 422, not a hang or corrupt tree (Task 5 `test_update_category_rejects_cycle`).

### Task 4: Tally computation and the books commit hook

**Files:**
- Create: `backend/app/services/shared_tally.py`, `backend/app/services/shared_links.py`
- Modify: `backend/app/books.py` (`session_for`), `backend/app/services/shared_budgets.py` (wire `on_member_added`)
- Test: `backend/tests/test_shared_tally.py`

**Interfaces:**
- Consumes: Task 1, 2, 3.
- Produces:
  - `shared_links.get_links(db, budget_id: int) -> list[SharedCategoryLink]`.
  - `shared_links.set_links(db, budget_id: int, links: list[tuple[int, int]], valid_shared_ids: set[int]) -> list[SharedCategoryLink]` — replaces all of the caller's links for that budget; `ValidationError` for an unknown category id, a category listed twice, or a shared id not in `valid_shared_ids`. Commits.
  - `shared_tally.compute(db, links: list[tuple[int, int]]) -> dict[tuple[int, int, int], Decimal]` — `(shared_category_id, year, month) -> sum`. Expansion algorithm (the part tests don't fully determine): load all categories `id -> parent_id`; for each category walk up its ancestors and take the **nearest** ancestor-or-self that has a link (so a child's own link beats its parent's); categories with no linked ancestor-or-self are dropped. Then one query: `SUM(Split.amount)` joined to `Transaction`, `WHERE Split.category_id IN (mapped ids)`, `GROUP BY Split.category_id, strftime('%Y'), strftime('%m')`, folded through the mapping. Links whose category doesn't exist are ignored.
  - `shared_tally.recompute_member(user_id: int) -> None` — for each `budget_ids_for_user`: valid shared ids = ids in that shared file; links filtered to them; `compute`; under `lock_for(budget_id)` delete the user's `MemberTally` rows and insert the new ones in one commit.
  - `shared_tally.rebuild_all() -> None` — every member of every registered budget; one user's failure is logged and doesn't stop the rest.
  - `shared_tally.install_hook(session: Session, user_id: int) -> None` — stores `user_id` in `session.info["books_user_id"]`; `after_flush` sets `session.info["shared_tally_dirty"]` when any of `session.new | session.dirty | session.deleted` is a `Transaction`, `Split`, `Category` or `SharedCategoryLink`; `after_commit` pops the flag and, if set, calls `recompute_member` inside `try/except Exception: logger.exception(...)`. Use `event.listen(session, ...)` per session.
  - `books.session_for` calls `shared_tally.install_hook(session, user_id)` (lazy import, avoiding a cycle).
  - `shared_budgets.on_member_added = shared_tally.recompute_member` (set at import time of `shared_tally`, which `app.main` imports via the router in Task 7; tests import `shared_tally` explicitly).
  - No bulk `update()/delete()` statements on `Transaction`, `Split` or `Category` exist today (audited: only `change_log` and `users` use bulk deletes, on other tables), so no bulk-event listener is needed; add a comment in `install_hook` saying a future bulk statement on these tables must set the flag itself.
